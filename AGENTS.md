# Hiroba app agent guide

Use Conventional Commits and independently versioned components. Keep canonical observability in observability/ and regenerate chart/pack outputs with the workflow library. Keep releaseComponents synchronized with selected component paths; artifact-bound smoke inherits its target identity. All external actions and reusable workflows use full commit SHAs with version comments. Never add classic Helm indexes, UI Release assets, mutable release callers, or real-environment smoke execution. Use only public Inari SDK contracts.

Mimir is the sole metrics backend/rule evaluator; never deploy a Prometheus server. Preserve central/local/client topology and exact pins for Mimir, Alertmanager, Grafana, Loki, Alloy, kube-state-metrics, node-exporter, and kubelet/control-plane collection. Scrape topology belongs in charts/RGDs; Alloy carries telemetry, not assets. Generated rule ConfigMaps and dashboard folder annotations come from the pinned workflow generator. Do not add Grafana identity sync, team/principal mapping, folder ACLs, access-readiness evidence, or direct-write components. Phase 3, release, deployed, and production gates are mandatory.
